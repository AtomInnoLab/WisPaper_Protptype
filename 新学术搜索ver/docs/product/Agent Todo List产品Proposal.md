# Agent Todo List 产品 Proposal

> 版本：V0.3 · 2026-08-14

## 1. 产品概述

Agent SDK 已提供 Todo List 工具，但产品尚未展示其返回的任务计划和执行状态。复杂任务执行期间，用户因此难以判断 Agent 正在做什么、还剩哪些步骤以及是否发生异常。

建议在 Agent 工作界面右侧增加 **Todo List 标签页**。当 Agent 调用该工具时自动出现，并随 Agent 执行实时更新。

Todo List 的定位是：

> Agent 执行过程的可视化窗口，而非独立任务管理器。

## 2. 产品目标

- 展示复杂任务的步骤、当前进度和异常状态；
- 减少用户反复询问进度、取消或重复提交任务；
- 提升用户对长任务执行过程的理解和信任；
- 复用 SDK 已有能力，验证不同模型调用 Todo 工具的稳定性。

## 3. 产品边界

| 维度 | 定义 |
|---|---|
| 数据来源 | Agent 调用 SDK Todo List 工具返回的结构化数据 |
| 创建方式 | Agent 根据任务复杂度自动调用；用户也可通过对话要求先制定计划 |
| 展示条件 | 工具被调用后才出现 Todo List 标签；简单任务不展示空列表 |
| 修改方式 | MVP 中用户通过对话要求 Agent 修改计划 |
| 生命周期 | 隶属于当前 Agent 任务，不跨任务聚合 |

MVP 不包含全局待办中心、Project 同步、复杂依赖、看板、多人协作和前端拖拽编排。

## 4. 触发规则

建议在以下任务中调用 Todo List：

- 包含多个明确步骤；
- 需要连续调用多个工具；
- 执行时间较长；
- 中途可能需要用户补充信息或确认。

简单问答、单次搜索和一步可完成的任务不调用。

用户说“先制定执行计划”“把任务拆成步骤”等时，Agent 应调用 Todo List 工具。MVP 不提供独立的手动创建按钮。

## 5. 核心流程

1. 用户提交任务。
2. Agent 判断是否需要 Todo List。
3. 工具首次返回后，右侧出现 Todo List 标签页。
4. Agent 开始执行，前端展示当前步骤。
5. Agent 写回状态后，列表同步更新并自动推进下一项。
6. 用户需要调整计划时通过对话提出，Agent 更新列表。
7. 任务结束后保留列表作为执行摘要。

## 6. MVP 功能

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 按需展示标签页 | 仅在 Todo 工具被调用后出现 |
| P0 | 展示任务列表 | 显示顺序、标题和状态 |
| P0 | 实时状态更新 | 消费 Agent 写回的数据，不由前端推断 |
| P0 | 进度摘要 | 显示“已完成 X / 总计 Y” |
| P0 | 完成态展示 | 已完成项显示勾选并弱化 |
| P0 | 失败态展示 | 清楚标识执行失败的步骤 |
| P0 | 对话修改计划 | 用户通过对话要求 Agent 调整步骤 |
| P0 | 模型兼容测试 | 验证当前支持模型的触发与更新能力 |
| P1 | 扩展状态 | 等待确认、阻塞、跳过 |
| P1 | 任务恢复 | 页面刷新或退出后恢复列表 |
| P1 | 关联产物 | Todo 关联论文、文件和工具结果 |
| P1 | 列表内操作 | 直接确认、重试或跳过任务 |

### MVP 状态

| 状态 | 展示 |
|---|---|
| 待执行 | 中性状态 |
| 进行中 | 蓝色动态状态 |
| 已完成 | 勾选并弱化标题 |
| 执行失败 | 红色异常状态 |

前端只展示 SDK 明确返回的状态，不自行判断任务是否完成。

## 7. 界面规则

- Todo List 与文件、检索结果等右侧工作区标签并列；
- 首次生成列表时自动打开标签页；
- 顶部展示整体进度，列表突出当前项和失败项；
- 点击任务可展开 SDK 返回的简短说明；
- 单项更新主要在列表中体现，对话区只提示计划创建、重大调整、失败和全部完成。

## 8. 实现职责

### Agent / 后端

- 开启 SDK Todo List 工具；
- 提供任务标识、顺序、标题和状态；
- 将新增、修改及状态变化同步给前端；
- 为不同模型提供一致的数据协议。

### 前端

- 识别 Todo 工具消息并动态展示标签页；
- 渲染任务列表、进度和状态变化；
- 保持同一会话中的列表状态。

## 9. 验证指标

| 方向 | 指标 |
|---|---|
| 工具触发 | 复杂任务触发率、简单任务误触发率 |
| 状态可信 | 状态更新成功率、状态与实际执行一致率 |
| 过程理解 | 用户能否准确判断当前步骤和剩余步骤 |
| 用户行为 | 主动询问进度次数、重复提交率、任务中止率 |
| 任务结果 | 复杂任务完成率 |

首轮使用文献综述、论文复现和批量论文筛选进行验证。

## 10. 待确认项

1. SDK 当前返回哪些字段和状态？
2. 状态变化采用全量列表还是增量事件？
3. 首版是否需要支持页面刷新后的恢复？
4. 哪些模型进入首轮兼容性测试？
5. Todo 首次出现时是否自动打开右侧标签页？

## 11. 下一步

使用真实 SDK 数据替换原型中的模拟列表，验证：

1. 复杂任务生成列表，简单任务不生成；
2. 执行过程中状态能够持续更新；
3. 用户通过对话修改计划后列表能够同步变化。
